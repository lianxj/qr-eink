## 1. 项目概述

**二维码设备** 低功耗蓝牙设备，核心功能：

- **BLE 远程下发**：手机 / PC 通过蓝牙向设备下发内容与命令
- **墨水屏显示二维码**：2.9 寸墨水屏（296×128），显示二维码（含图片）
- **RTC 时钟** 实时时钟，支持定时刷新（报警 / 周期两种方式）
- **安全二维码**：时间 AES-128 加密（模式 A）；或 URL+时间整体加密（模式 B）
- **会话认证**：所有写操作需 `!AUTH` 认证，认证密码独立持久化，防止公开放置时被恶意篡改
- **全参数掉电保存**：业务文本、AES 密钥、认证密码、定时配置均持久化到 Flash
- **背景图持久化 + 二维码叠加**：图片作为背景存 Flash，二维码/时间叠加显示
- **RLE 图片压缩**：图片传输压缩 ~90%，大幅缩短传输时间
- **BLE 控制 LED**：亮 / 灭 / 闪烁（非阻塞）
- **电池电量检测**：采样 VBAT，`!BATT` 查询电压/电量
- **远程改 MAC + 软件复位**：`!MAC` 修改蓝牙地址（Flash 持久化），`!RBT` 看门狗复位生效
- **低功耗 + 磁开关唤醒**：深睡待机，磁铁触发广播，RTC 报警定时刷新

典型用途：电子价格牌、门禁访客码、临时通行凭证等需要"定时变化 + 加密可验证"的二维码场景。

## 2. BLE 通信接口

### 2.1 广播

| 项       | 值                                                                           |
| -------- | ---------------------------------------------------------------------------- |
| 设备名   | **`QR-EINK`**                                                                |
| 广播类型 | 可连接非定向广播                                                             |
| 典型 MAC | `a4:c1:38:cb:5d:4c`（以实际为准）                                            |
| 广播触发 | **上电直接广播**，30s 无连接自动深睡；磁铁/RTC 唤醒后按唤醒源行为（详见 §5） |

### 2.2 GATT 服务

| 项                     | UUID         | 属性                           |
| ---------------------- | ------------ | ------------------------------ |
| 自定义服务             | **`0xFFE0`** | —                              |
| RX 特征（手机 → 设备） | **`0xFFE2`** | write / write-without-response |
| TX 特征（设备 → 手机） | **`0xFFE1`** | read / notify                  |

- **MTU：200**（连接后协商）
- **TX notify 单帧回执上限 64 字节**
- 命令以 UTF-8 文本帧下发（支持 write-without-response，速度更快）

### 2.3 通信模型

```
手机/PC ──write──▶ 0xFFE2   下发命令文本（如 "!ETIME"、任意文本二维码）
设备   ──notify──▶ 0xFFE1   回执（"OK:xxx" / "ERR:xxx" / 状态报告）
```

图片传输为二进制帧（见 §3.2 的 `!IMG`）。

| ------------------------ | ------------------------------------------------------------------------------ | ------------------------------------------------- |

| `!TIME`                  | 显示明文时间二维码                                                             | `OK:TIME`                                         |
| `!ETIME`                 | 显示加密时间二维码（按当前加密模式）                                           | `OK:ETIME`                                        |
| `<任意文本>`             | 显示文本二维码（非 `!` 开头即显示内容）                                        | `OK`                                              |
| `!TEXT <文本>`           | 保存业务文本（独立于显示文本，≤70 字符）                                       | `OK:TEXT`                                         |
| `!TEXT`（空）            | 清空业务文本                                                                   | `OK:TEXT`                                         |
| `!R` / `!REDISPLAY`      | 重显上一帧                                                                     | `OK:R`（有文本）/ `OK:R-TIME`                     |
| `!CLR` / `!CLEAR`        | 清屏                                                                           | `OK:CLR`                                          |
| `!SLP` / `!SLEEP`        | 屏幕休眠                                                                       | `OK:SLP`                                          |
| `!ALARM mm`              | 设单点报警：分钟                                                               | `OK:ALARM` / `ERR:ALARM`                          |
| `!ALARM hhmm`            | 设单点报警：时+分                                                              | `OK:ALARM` / `ERR:ALARM`                          |
| `!ALARM OFF`             | 关闭单点报警                                                                   | `OK:ALARM`                                        |
| `!ALARMTEST`             | 立即模拟报警（刷新加密二维码）                                                 | `OK:TEST`                                         |
| `!ALARMSTAT`             | 查询配置状态（见下）                                                           | 状态报告                                          |
| `!PERIOD N`              | 周期刷新：每 N 分钟（1-255）                                                   | `OK:PERIOD` / `ERR:PERIOD`                        |
| `!PERIOD 0` / `OFF`      | 关闭周期刷新                                                                   | `OK:PERIOD`                                       |
| `!AESKEY`                | 查询当前密钥                                                                   | `OK:AESKEY <32hex>`                               |
| `!AESKEY <32hex密文>`    | **加密更新**：密文 = AES-128-ECB(当前密钥, 新密钥)，旧/新密钥均不明文传输      | `OK:AESKEY` / `ERR:AESKEY` / `ERR:AESKEY:DECRYPT` |
| `!AUTH <32hex密文>`      | **会话认证**：密文 = AES-128-ECB(当前密钥, 认证密码)，认证成功后才能执行写操作 | `OK:AUTH` / `ERR:AUTH`                            |
| `!AUTHPASS <32hex密文>`  | **更新认证密码**（需先认证）：密文 = AES-128-ECB(当前密钥, 新密码)             | `OK:AUTHPASS` / `ERR:AUTHPASS`                    |
| `ERR:AUTH`               | 未认证时执行写操作的统一拒绝回执                                               | —                                                 |
| `!MODE`                  | 查询加密模式                                                                   | `OK:MODE 0/1`                                     |
| `!MODE 0`                | 模式 A：URL 明文 + 时间加密                                                    | `OK:MODE 0`                                       |
| `!MODE 1`                | 模式 B：URL+时间整体加密                                                       | `OK:MODE 1`                                       |
| `!IMG`                   | 开始接收图片（原始，向后兼容）                                                 | `OK:IMG`                                          |
| `!IMG 1`                 | 开始接收图片（**RLE 压缩**，推荐）                                             | `OK:IMG`                                          |
| `0xAA` 二进制帧          | 图片数据分片（见下）                                                           | （无回执）                                        |
| `!IMGEND`                | 图片接收完成：保存为背景 + 刷新                                                | `OK:IMG`                                          |
| `!LED`                   | 查询 LED 状态                                                                  | `LED:ON` / `LED:OFF`                              |

| `!RBT` / `!REBOOT`       | 软件复位（看门狗 1ms 超时触发），先回 `OK:RBT` 再复位                          | `OK:RBT`                                          |

### 3.1 `!ALARMSTAT` 状态报告

```
A=<报警使能0/1> AH=<报警小时,FF=每小时> AM=<报警分钟> P=<周期使能0/1> PM=<周期分钟> M=<加密模式0/1> K=<密钥来源0默认/1自定义> T=<业务文本长度>
```

示例：`A=1 AH=14 AM=30 P=0 PM=00 M=1 K=1 T=24`

### 3.2 图片传输协议（`!IMG` / `!IMG 1`）

图片作为**背景图**持久化到 Flash（掉电不丢），之后的二维码/时间叠加显示在背景上。

1. 发 `!IMG`（原始）或 `!IMG 1`（RLE 压缩）→ 设备进入图片接收模式, 回 `OK:IMG`
2. 逐帧发送二进制分片（写入 0xFFE2）：

```
帧格式: 0xAA | seq_hi | seq_lo | data...
  seq   = 16 位递增序号（每帧 +1，可忽略/用于校验）
  data  = 帧缓冲字节（原始）或 RLE 压缩字节（!IMG 1）
```

3. 发 `!IMGEND` → 设备**保存为背景 + 刷新**，回 `OK:IMGEND`

帧缓冲格式（与屏驱动一致）：

```
128 宽 × 296 高，1bit（1=白，0=黑）
行优先，每行 16 字节，MSB-first
总字节数 = (128/8) × 296 = 4736 字节
```

#### RLE 压缩格式（`!IMG 1`）

| 控制字节      | 含义                                | 数据                   |
| ------------- | ----------------------------------- | ---------------------- |
| `0x00`–`0x7F` | 字面量游程，长度=控制+1             | 后跟 length 个原样字节 |
| `0x80`–`0xFF` | 重复游程，次数=控制-0x80+1（1~128） | 后跟 1 个值字节        |

- 设备端流式解压（跨包安全，不占额外 RAM）
- 实测背景图 4736B → 约 462B（9.8%），传输包数减少约 10 倍
- PC 端编码与设备解码已做往返一致验证

> 图片需要发送方先缩放到 128×296、白底、二值化后再分片。

## 4. 加密方案

### 4.1 共享密钥

- 算法：**AES-128**
- 出厂默认密钥（**占位值，正式部署务必更换**）：
  ```
  00112233445566778899AABBCCDDEEFF
  ```
- 通过 `!AESKEY <32hex密文>` 在线更换，**密文 = AES-128-ECB(当前密钥, 新密钥)**，旧密钥和新密钥均不明文传输，持久化到 Flash
- 设备端用当前密钥解密密文得到新密钥，校验非全0/全FF后更新
- **仅支持加密方式**，明文方式已移除
- 更换后 **设备端与解码端必须使用相同新密钥**

**加密更新流程**：

```
PC端:  密文 = AES-128-ECB(当前密钥, 新密钥)   →  发送 !AESKEY <32hex密文>
设备端: 新密钥 = AES-128-ECB解密(当前密钥, 密文) → 校验非全0/全FF → 更新+持久化
```

- 旧密钥和新密钥均不明文传输，抓包只能看到 32hex 密文
- 设备端校验解密结果非全0/全FF（防篡改），通过后更新并持久化到 Flash

### 4.2 会话认证（!AUTH）

**为什么需要认证**：设备公开放置，BLE 无配对，任何人都能连接。未认证时只能执行读操作（查询状态/电量/显示时间二维码），所有写操作（修改文本/密钥/模式/报警/图片/MAC/复位等）必须先通过 `!AUTH` 认证。

**认证流程**：

```
PC端:  密文 = AES-128-ECB(当前AES密钥, 认证密码)  →  发送 !AUTH <32hex密文>
设备端: 密码 = AES-128-ECB解密(当前AES密钥, 密文) → 与保存的认证密码比较 → OK:AUTH / ERR:AUTH
```

- 认证密码 16 字节（32hex），独立于 AES 加密密钥，持久化到 Flash
- 默认密码 = `00112233445566778899AABBCCDDEEFF`（占位，生产必须更换）
- 认证状态在 **断开连接后自动清除**，下次连接需重新认证
- 密码不明文传输，抓包只能看到密文
- 通过 `!AUTHPASS <密文>` 可在线更换认证密码（需先认证）

**无需认证的读操作**：`!TIME` / `!ETIME` / `!R` / `!BATT` / `!ALARMSTAT` / `!AESKEY`(查询) / `!MODE`(查询) / `!LED`(查询) / `!MAC`(查询)

**必须认证的写操作**：`!TEXT` / `!SYNC` / `!AESKEY`(更新) / `!MODE`(设置) / `!ALARM` / `!PERIOD` / `!IMG` / `!LED`(设置) / `!MAC`(设置) / `!RBT` / `!CLR` / `!AUTHPASS`

### 4.3 模式 A（默认）：URL 明文 + 时间加密

- 二维码内容：`<文本>?t=<32位hex密文>`（文本不含 `?` 时用 `?`，含 `?` 用 `&`）
- 参数名固定为 `t`
- **时间加密**：对 16 字节明文做单块 AES-128-ECB

时间明文布局（16 字节，设备端构造）：

| 偏移  | 内容                 |
| ----- | -------------------- |
| 0     | 年 BCD               |
| 1     | 月 BCD               |
| 2     | 日 BCD               |
| 3     | 时 BCD               |
| 4     | 分 BCD               |
| 5     | 秒 BCD               |
| 6     | 星期 BCD（0=周日）   |
| 7     | nonce（每次刷新 +1） |
| 8     | `'Q'` (0x51)         |
| 9     | `'R'` (0x52)         |
| 10    | 版本 0x01            |
| 11-15 | 0 填充               |

- 密文 16 字节 → 32 个 hex 字符
- 解码端校验偏移 8/9/10 的魔数，可检测密钥错误

### 4.4 模式 B：URL + 时间整体加密

- 二维码内容：**hex 字符串密文**（文本模式 QR，全可打印字符，扫码器兼容性最好），外部完全不可读
- 明文 payload：`<文本>?t=<YYMMDDHHMMSS>`（12 位紧凑时间，与 `!SYNC` 同格式）
- 加密：**AES-128-CBC**，整串加密一次（时间**不再**单独 AES，避免二次加密）

CBC 参数（解码端需一致）：

```
算法:      AES-128-CBC（无填充，手动 0 填充）
IV:        0102030405060708090A0B0C0D0E0F10
明文帧:    [0] = payload 长度(1B)
           [1..] = payload（文本?t=YYMMDDHHMMSS 或纯 YYMMDDHHMMSS）
           末尾 0x00 填充到 16 字节倍数
```

- 解码流程：扫码得 hex 字符串 → hex 解码 → CBC 解密 → 读长度字节 → 得 payload → 直接解析 `t=` 后的明文时间
- 模式 B 下文本自动截断到 **48 字符**（保证二维码可扫）

### 4.5 两种模式对比

|              | 模式 A（`!MODE 0`）      | 模式 B（`!MODE 1`）    |
| ------------ | ------------------------ | ---------------------- |
| 二维码内容   | 明文 URL + 加密时间      | 整体密文（hex 字符串） |
| URL 是否可见 | 可见                     | 不可见                 |
| 时间加密方式 | AES-ECB（单独）          | CBC（随整串）          |
| 文本上限     | 70                       | 48                     |
| 解码         | 提取 `t=` → ECB 解密     | CBC 解密 → 读明文时间  |
| 适用         | 链接可公开、只要时间防伪 | URL 本身需保密         |

## 5. 低功耗与磁开关唤醒

设备采用"深睡 + GPIO 唤醒"的低功耗设计，**上电自动广播**（30s 无连接深睡），磁铁/RTC 唤醒后按唤醒源行为，RTC 报警负责定时刷新。

### 5.1 行为流程

| 触发                        | 行为                                                             |
| --------------------------- | ---------------------------------------------------------------- |
| 上电                        | 显示加密二维码 → **开广播** → 30s 无连接后深睡                   |
| 磁开关触发（磁铁靠近/离开） | 开启广播 → **30s 内无连接自动关广播**；连接中断开后重启 30s 窗口 |
| RTC 报警唤醒                | 刷新加密二维码 → 回深睡（**不广播**）                            |
| 唤醒源不明                  | 立即回深睡                                                       |
